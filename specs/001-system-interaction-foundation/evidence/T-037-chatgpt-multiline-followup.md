# Finding 5 后续：ChatGPT 多行闭环专项验证

## 任务边界

- 来源：Solar 对 `ebb6978` 的 Implementation Gate REVIEW，Finding 5（MUST）——
  ChatGPT 代表性多行验证缺失，原豁免理由（"回车即发送消息"）不成立。
- 目标：取得 Plan 第 327 行要求的"Chrome/ChatGPT 代表性多行完整闭环"证据。
- 本文件只记录多行专项验证；T-037 的其余覆盖不受影响。

## 验证环境

- Mac：MacBook Pro（Mac15,3，Apple M3，8 GB）
- macOS：26.5.2（25F84）
- 目标应用：Google Chrome 150.0.7871.184（chatgpt.com），输入框 role=AXTextArea
- 应用构建：Debug、universal，代码状态 `1ce9d01`
- 夹具：两行合成文字，71 UTF-16 code unit、1 个换行
  - 第一行含中英混合，第二行含 emoji 😀 与组合字符 é
  - 转换结果 80 UTF-16 code unit、2 个换行
- 验证日期：2026-07-30

## 驱动方式

夹具通过 `pbcopy` 放入剪贴板后，用 System Events 模拟 **⌘A + ⌘V** 真实粘贴，
使 ChatGPT 的前端更新链路（React 重渲染、自适应高度、草稿保存）与真人操作
一致；随后模拟 ⌃⌥⌘P，并通过辅助功能 API 点击面板按钮。

**方法论修正（重要）：** 2026-07-29 的一次"验证通过"是无效的——当时用 AX
直接写入夹具，等于"用 AX 写入验证 AX 写入能力"，构成循环论证，且真人复测
即失败。本轮改用模拟粘贴，前端链路被真实触发，结论才成立。

## 结果：多行闭环成功（5 / 5）

| 场景 | 预览状态 | 确认后状态 |
| --- | --- | --- |
| 连续运行 1 | 优化结果已准备好，确认后才会替换原文。 | 已替换所选文字，原文仍可恢复。 |
| 连续运行 2 | 同上 | 同上 |
| 连续运行 3 | 同上 | 同上 |
| 预览停留 10 秒后确认 | 同上 | 同上 |
| 预览停留 20 秒后确认 | 同上 | 同上 |

五次运行的替换与恢复全部成功；恢复后面板正常关闭，会话结束。

## 关键观察：写入是异步应用的

替换与恢复两个方向的诊断数据完全一致（诊断为临时埋点，只记长度与错误码，
不含内容，采集后已回退）：

```text
bridge.replace handleNil=false pidNil=false mode=wholeField
validate passed expectedLen=71
setText attr=AXValue writeLen=80 nl=2 axError=0 cachedIsFocused=true
        cachedLen=71 focusedLen=71 afterLen=71
恢复方向：writeLen=71 nl=1 axError=0 cachedLen=80 focusedLen=80 afterLen=80
```

- `axError=0` 且 `cachedIsFocused=true`：写入调用成功，缓存元素始终等于系统
  当前焦点元素，元素身份未失效。
- **`afterLen` 恒等于写入前的长度**：`setText` 返回后立即回读，拿到的仍是旧值。
  多行写入必须依靠既有的回读重试（最多 5 次、约 500ms，见
  `evidence/T-033-chrome-chatgpt-closed-loop.md`）才能确认成立。
- 预览停留 10 秒与 20 秒同样成功，说明"确认前长时间停留导致目标内容变化"
  这一假设不成立。

## 已知限制：间歇失败，复现条件未确定

2026-07-29 的多次人工验证中，同样的多行替换**反复失败**并显示
`未能安全替换原文，结果仍可复制。`；2026-07-30 的五次自动验证全部成功。
两者代码状态相同，因此该行为是**间歇性**的，复现条件尚未确定。

已通过实测排除的假设：

1. 换行符形式——LF、CR、CRLF、U+2028、U+2029 五种形式写入均生效。
2. 元素来源——系统级与应用级焦点查询返回 `CFEqual` 相同的元素，两者均可写。
3. 引用陈旧——持有捕获引用 6 秒后写入仍成功。
4. 增强辅助功能模式的启用时序——补 500ms settle delay 后仍失败（该改动已回退）。
5. 预览面板占据窗口焦点——面板上屏时写入仍成功。
6. 确认前停留时长——10 秒与 20 秒均成功。

失败侧的唯一硬数据来自 2026-07-29 17:23 的一次采集：
`bridge.replace handleNil=false pidNil=false mode=wholeField` 已输出，但当时
`validate` 的 A1–A4 分支尚未埋点，因此确定失败发生在
`AccessibilityGateway.validate` 的 A1–A4（应用存活、外部 PID、窗口身份、
元素身份）之一，而非写入本身。

**结论定性：** ChatGPT 多行闭环已可复现成功，Plan 第 327 行要求的证据成立；
但存在未定位的间歇失败，应作为特定应用限制记录，并在后续 Feature 或
P6 复核中继续观察。

## 建议（不在本任务范围内实施）

1. **保留 A1–A4 与写入路径的诊断埋点能力**。本轮定位过程证明：缺少这些埋点
   时，失败会被错误归因（先后误判为"Chromium 拒绝多行写入""元素被重建"
   "换行符不被接受"），共浪费七轮外部探针。埋点只记录长度、错误码与布尔标志，
   不含任何文字内容，符合 FR-013 与 NFR-006。
2. **修正失败归类**。`GatewaySessionTextTarget.replace` 在前置条件不满足时
   返回 `false`，最终呈现为 `writeFailed`（"未能安全替换原文"），文案暗示
   曾尝试写入。当失败发生在写入之前时，应给出准确状态，否则违反 NFR-007
   的"可理解说明"要求。

## 验证环境注意事项

每次重建二进制后，macOS 会使辅助功能授权失效——系统设置里的开关**仍显示
为开启**，但 TCC 记录已与新的可执行文件不匹配，应用会持续报告需要权限。
必须将开关关闭再打开。该操作可自动完成：定位
`checkbox "SystemInteractionFoundation"` 后点击两次即可，无需人工干预。
该注意事项应写入验收包的已知限制，避免后续验证被误判为权限缺陷。
