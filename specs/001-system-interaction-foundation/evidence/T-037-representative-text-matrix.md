# T-037 代表性文字矩阵验证证据

## 任务边界

- 任务：T-037 [Verification] 验证代表性文字矩阵。
- 依赖：T-032、T-033、T-034。
- 覆盖：FR-006、NFR-004、AC-007、AC-016。
- 要求记录：中文、英文、中英混合、空文本、多行、10,000 字符长文本和
  特殊字符；记录具体长度与应用限制，核对无崩溃、静默截断或无关修改。

## 验证环境

- Mac：MacBook Pro（Mac15,3，Apple M3，8 GB）
- macOS：26.5.2（25F84）
- 目标应用：TextEdit 1.20；Google Chrome 150.0.7871.184（chatgpt.com）
- 应用构建：Debug、universal，代码状态 `8b75e6f`
- 输入内容：全部为 `SYNTHETIC-001` 标记的合成文字，由验证脚本生成到
  `/tmp` 临时文件或剪贴板，验证结束后删除
- 验证日期：2026-07-28

## 夹具准备方式

- TextEdit：脚本生成临时文本文件后用 TextEdit 打开，操作者手动选取。
  夹具写入只使用 TextEdit 自身的 Apple Event，不经 System Events，
  避免 T-035 记录过的辅助功能树干扰。
- ChatGPT：脚本用 `pbcopy` 将夹具放入剪贴板，操作者手动 ⌘V 粘贴。
  该剪贴板写入来自外部验证脚本，不是被测应用行为，NFR-006 的
  "应用不得自动触碰剪贴板"约束不受影响。

## 结果一：TextEdit（选区路径，操作者手动拖选）

同一文档内 5 段，逐段选中 → ⌃⌥⌘P → 确认替换 → 核对 → 恢复原文。
全部成功，无崩溃、无截断、无无关修改（操作者反馈 2026-07-28："成功了"）。

1. 纯中文（约 34 字符）：`SYNTHETIC-001 纯中文段落，用于验证中文选区读取与替换的逐字保真。`
2. 纯英文（约 74 字符）：`SYNTHETIC-001 plain English paragraph for byte-exact selection verification.`
3. 中英混合（约 47 字符）：中英文交错排列。
4. 多行（3 行，含 2 个换行符）：三行连续文本一次性选中。
5. 特殊字符（约 60 字符）：全角标点 `【】「」…—–“”‘’`、制表符、
   ASCII 符号 `@#$%^&*()_+{}|:<>?~`、emoji `😀🎉`、
   组合字符 `é`（U+0065 + U+0301 组合形式）。

## 结果二：TextEdit（无选区全文路径，10,000 字符长文本）

- 夹具：`SYNTHETIC-001 长文本测试片段。` 重复填充，精确 10,000 字符
  （`wc -m` 校验），尾部故意切在半个标记上（`…片段。SYNTHETIC-00`），
  便于发现静默截断。
- 操作：光标置于文档内、不选中 → ⌃⌥⌘P → 确认替换 → 核对首尾 → 恢复原文。
- 结果：成功。开头为 `【系统交互验证】` 后接原文，尾部保持
  `长文本测试片段。SYNTHETIC-00` 未被截断（操作者反馈："成功了"）。

## 结果三：ChatGPT（无选区全文路径）

1. 中英混合 + 特殊字符合并段（100 字符，含 emoji `😀🎉` 与组合字符 `é`）：
   粘贴 → ⌃⌥⌘P → 确认替换 → 恢复原文，全部成功，emoji 与组合字符
   未出现乱码，标点未丢失（操作者反馈："成功"）。
2. 10,000 字符长文本（同结果二夹具）：粘贴 → ⌃⌥⌘P → 确认替换 →
   核对首尾 → 恢复原文，成功，无截断（操作者反馈："成功"）。
   本轮未触发 `writeFailed`，说明既有的回读重试（最多 5 次、约 500ms，
   见 `evidence/T-033-chrome-chatgpt-closed-loop.md`）在一万字符规模下
   仍然足够。

## 覆盖范围说明（如实记录）

- **空文本**：不在本任务重复执行。TextEdit 空文档触发已在 T-035 矩阵第 1 项
  验证为 `emptyOrUnsupported` 并零写入，见
  `evidence/T-035-permission-safety-recovery-matrix.md`。
- **ChatGPT 侧的纯中文与纯英文**：未单独执行，由"中英混合 + 特殊字符"
  合并段同时覆盖两种文字系统。
- **ChatGPT 侧的多行**：未执行。ChatGPT 输入框中回车即发送消息，无法在
  不产生真实网络请求的前提下构造稳定的多行夹具；多行路径已在 TextEdit
  结果一第 4 项验证。该取舍属于目标应用交互限制，不是实现缺陷。

## 结论

代表性文字矩阵在两个必须支持的应用中均通过：中文、英文、中英混合、
多行、特殊字符（含 emoji 与 Unicode 组合字符）、10,000 字符长文本逐字
保真，空文本走 fail-closed 路径。全过程无崩溃、无静默截断、无对选区外
文字的无关修改，FR-006、NFR-004、AC-007、AC-016 达成，未触发硬停止条件。
上节记录的三项覆盖取舍不影响判定。
