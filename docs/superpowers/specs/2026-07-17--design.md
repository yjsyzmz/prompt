# 系统级 Prompt 复用与优化应用——产品设计文档

## 1. 文档状态

- 日期：2026-07-17
- 状态：产品方向与首版设计已确认
- 平台：macOS 首发
- 命名说明：本设计阶段不定义正式产品名和功能名。文中的“提示词”“优化规则”“统一入口”“工作台”“悬浮预览”等仅为便于沟通的临时术语，后续应通过品牌与交互设计单独命名。

## 2. 产品概述

这是一款面向一切经常使用 Prompt 的用户的 macOS 系统级效率应用。用户可以在任意可输入文字的应用中，通过统一的全局入口快速调用个人提示词，或将当前零散表达转换成更清晰、结构化、适合提交给生成式 AI 的 Prompt。

应用由工作台和系统级浮动交互组成：工作台用于积累、组织和编辑个人提示词及优化规则；浮动交互用于在不中断当前任务的情况下完成搜索、变量填写、优化预览和确认插入。

产品坚持“用户确认后才改变原文”。优化结果先在当前输入区域附近预览，用户可确认替换、复制、重新生成或取消，应用不会自动覆盖用户输入。

## 3. 背景与问题

高频使用生成式 AI 的用户通常面临以下问题：

1. 有价值的 Prompt 分散在文档、聊天记录、便签和剪贴板中，难以在需要时快速找到并复用。
2. 用户往往先写出零散、口语化或信息结构不完整的内容，再手动整理成适合 AI 理解的 Prompt，过程重复且打断思路。
3. 不同任务需要不同的优化方法，例如严谨重组、合理补全、压缩表达或转成指定结构，但现有工具缺少可复用、可切换的优化规则。
4. 浏览器插件或单一 AI 产品内部功能无法覆盖用户在浏览器、办公、聊天和编辑器等不同应用中的输入场景。

## 4. 产品目标

### 4.1 首要目标

构建具有较高产品与技术完成度的系统级 Prompt 工具，完整展示以下能力：

- 跨应用文字读取与插入。
- 全局快捷入口与上下文浮动交互。
- Prompt 管理、搜索和变量模板。
- 可复用的 AI 优化规则。
- 多模型服务连接与流式结果展示。
- 本地安全存储、权限处理和可靠的失败后备路径。

### 4.2 次要目标

- 获得真实安装、激活和首次成功使用的用户。
- 在用户同意匿名统计的前提下，观察重复使用、周活跃和留存趋势。

### 4.3 非目标

首版不包含：

- 公开社区、提示词分享与内容审核。
- 账号体系、云端同步与多人协作。
- 产品方提供的内置 AI 额度。
- 订阅、支付或复杂计费系统。
- Windows 版本。
- 自行托管或随应用分发的开源模型。
- 以完全相同的控制方式兼容所有第三方应用。

## 5. 目标用户与典型场景

目标用户是一切经常使用 Prompt 的人，包括但不限于产品经理、开发者、设计师、运营人员、研究人员和内容创作者。

典型验证场景：产品经理在 ChatGPT 中输入一段随意的需求描述，通过全局入口选择合适的优化规则，在输入框附近预览结构化结果，确认后替换原文。

产品能力不以产品经理为边界。上述场景用于验证核心流程，其他职业可通过不同提示词和优化规则复用同一套产品能力。

## 6. 核心产品原则

1. **系统级通用**：能力存在于用户当前工作流之上，而非绑定单一网站或 AI 产品。
2. **一个入口**：调用提示词和优化当前文字共用一个全局入口，降低记忆成本。
3. **确认后修改**：原文在用户确认前保持不变。
4. **选区优先**：有选中文字时只处理选区；无选区时处理当前输入框全文。
5. **手动优先**：默认通过快捷键主动触发，实时优化由用户明确开启。
6. **本地优先存储**：个人数据默认保存在本机，API Key 进入系统安全凭据存储。
7. **始终可完成**：直接读取或插入失败时，通过剪贴板提供可靠后备流程。
8. **界面保持克制**：把不同优化方向、语气、结构和补全策略统一为可切换的优化规则，避免堆叠大量独立开关。

## 7. 方案选择

本产品采用“双核心工作台”方案：提示词复用与文字优化并列存在，通过同一个全局入口连接。

未选择仅做提示词启动器，是因为其实现稳定但与传统文本扩展或剪贴板工具差异有限；未选择只做实时优化悬浮层，是因为虽然记忆点强，但无法覆盖用户积累与复用 Prompt 的核心需求，并会放大系统兼容性风险。

首版将稳定的手动模式作为发布核心，实时模式作为增强能力。开发顺序必须先解决跨应用读取、预览、确认和插入，再扩展模板与实时生成。

## 8. 核心概念

### 8.1 提示词

提示词是可直接复用并插入当前输入位置的内容。它分为两类：

- 固定提示词：每次调用时内容一致。
- 变量模板：正文包含需在调用时填写的变量，应用根据变量生成最终文本。

变量具有名称、说明、默认值和是否必填等属性。例如，一个产品需求模板可要求用户填写产品名称、目标用户和核心问题。

### 8.2 优化规则

优化规则用于把当前输入转换成更适合目标任务的 Prompt。它统一承载：

- 是否仅整理已有信息或允许合理补全。
- 目标结构、语气与长度。
- 特定任务要求。
- 模型应遵循的指导内容。

首版提供少量基础预设，覆盖严谨整理、合理补全、表达精炼和结构化输出等常见目标。用户可以复制并修改预设，也可以自行创建规则。正式名称和预设文案在后续内容设计中确定。

### 8.3 临时要求

用户在执行某次优化时可以补充只对本次生效的要求，例如“更专业”“补充验收标准”或“控制在 300 字以内”。临时要求不改变原优化规则，除非用户主动保存为新规则。

## 9. 核心使用流程

### 9.1 首次使用

1. 用户安装应用并授予必要的 macOS 系统权限。
2. 应用用简短演示说明全局入口、提示词调用和文字优化。
3. 用户选择模型服务商，跟随教程申请并填写 API Key。
4. 应用测试接口地址、Key 和模型是否可用。
5. 连接成功后，应用引导用户完成第一次优化。
6. 用户无需注册账号即可进入工作台并使用全部首版核心功能。

API 指引应解释 Key 的含义、费用承担方和保存位置，提供服务商官方申请入口与图文步骤，并标注免费额度政策可能变化。教程内容应可独立更新，不依赖重新发布桌面应用。

### 9.2 调用已有提示词

1. 用户在任意输入位置唤起全局入口。
2. 入口展示搜索、最近使用、收藏及与当前上下文相关的候选内容。
3. 用户搜索并选择一个提示词。
4. 固定提示词可预览后插入；变量模板先显示轻量填写界面。
5. 应用校验必填变量并生成完整文本。
6. 用户确认后，文本插入当前光标位置。

### 9.3 优化当前文字

1. 用户选中文字；没有选区时，应用尝试读取当前输入框全文。
2. 用户唤起统一入口并选择一个优化规则，也可补充临时要求。
3. 应用组合原文、规则和临时要求，请求用户配置的云端模型。
4. 结果以流式方式显示在当前输入区域附近，原文保持不变。
5. 用户可以确认替换、复制结果、重新生成或取消。
6. 直接插入失败时，应用保留结果并提供一键复制。

### 9.4 实时模式

1. 用户主动开启实时模式，应用持续显示当前状态。
2. 输入达到最低长度且停止一段时间后，应用才发起优化请求。
3. 用户继续输入时，过期请求被取消，旧结果不得覆盖新内容。
4. 预览随内容更新，但不会自动修改原文。
5. 用户可以随时暂停实时模式，并可针对特定应用禁用。
6. 调用频率过高时，应用自动延长触发间隔，并提醒调用将消耗用户自己的 API 额度。

统一入口的具体布局、快捷键和功能文案不在本设计中固定，后续通过原型和用户测试优化；本设计只约束其行为原则。

## 10. 工作台信息架构

工作台包含以下功能区域，正式名称后续确定：

- 首页：最近使用、收藏内容、常用优化规则和快速新建。
- 提示词库：创建、编辑、搜索、分类和调用提示词。
- 优化规则库：管理基础预设和用户自定义规则。
- 模型连接：配置服务商、接口地址、模型和 API Key。
- 设置：配置全局快捷键、实时模式、排除应用、隐私和数据管理。

## 11. 数据模型与存储原则

### 11.1 提示词数据

- 唯一标识。
- 标题与正文。
- 固定内容或变量模板类型。
- 变量定义：名称、说明、默认值和是否必填。
- 文件夹、标签和收藏状态。
- 创建时间、修改时间和最近使用时间。

### 11.2 优化规则数据

- 唯一标识。
- 名称与用途说明。
- 发送给模型的指导内容。
- 信息补全策略。
- 输出结构、语气和长度偏好。
- 默认或收藏状态。
- 创建时间、修改时间和最近使用时间。

### 11.3 模型连接数据

- 服务商类型。
- 接口地址。
- 模型标识。
- 连接状态和最近测试时间。
- 安全凭据引用，不包含明文 API Key。

首版只实现一套经过验证的 OpenAI 兼容请求协议，以控制开发和测试范围。应用可以为少量已验证服务商提供配置预设，同时允许高级用户填写兼容的自定义接口地址和模型标识。使用非兼容协议的服务商不属于首版支持范围；后续通过模型适配层逐个增加。

### 11.4 数据原则

- 提示词、优化规则和设置默认保存在本机。
- API Key 存入 macOS 安全凭据存储。
- 默认不保存用户在其他应用中输入的原文和生成结果。
- 用户可主动把满意的优化结果保存为新提示词。
- 最近使用只记录对象标识和时间，不记录被处理的正文。
- 支持本地数据导入与导出，为备份及未来云同步提供迁移路径。

## 12. 技术架构

第一版采用原生 macOS 应用架构，以提高全局快捷键、系统权限、文本读取、光标定位和悬浮窗口的可靠性。未来支持 Windows 时，应保留可复用的数据模型和模型适配逻辑，但不以牺牲首版 macOS 体验为代价提前构建跨平台框架。

核心组件：

- **工作台界面**：管理提示词、变量模板、优化规则、模型连接和设置。
- **全局交互层**：监听快捷键，识别当前应用、选区、输入框内容和光标位置。
- **浮动交互层**：承载统一入口、变量填写和优化结果预览。
- **模板引擎**：解析变量、校验必填项并生成最终文本。
- **优化引擎**：组合原文、优化规则和临时要求。
- **模型适配层**：统一不同服务商的接口、流式输出、错误格式和模型配置。
- **本地数据层**：保存提示词、优化规则、偏好和非敏感使用元数据。
- **安全凭据层**：通过 macOS 系统能力保存 API Key。
- **匿名统计层**：仅在用户同意后发送非内容型产品事件。

## 13. 优化请求数据流

1. 用户唤起全局入口。
2. 全局交互层优先读取选区；无选区时尝试读取当前输入框全文。
3. 优化引擎把原文、优化规则和临时要求放入明确分隔的请求结构，降低原文被误当成系统指令的风险。
4. 模型适配层使用本机安全存储中的 Key，直接请求用户选择的模型服务。
5. 流式结果进入悬浮预览。
6. 用户确认后，全局交互层尝试替换原选区或输入框内容。
7. 替换失败时，结果保留并进入剪贴板后备流程。

首版不需要账号或业务数据服务器。可更新教程可以使用静态在线内容；匿名统计可以使用轻量、隐私友好的统计服务。两者均不得接收用户正文、生成结果或 API Key。

## 14. 权限、隐私与安全

- 仅在用户主动触发或明确开启实时模式后读取必要文本。
- 密码框和安全输入区域不读取、不处理。
- 权限不足时解释缺失权限、受影响能力和授权路径。
- 自定义接口地址必须提示内容将发送给第三方服务。
- API Key 不进入普通配置、日志或匿名统计。
- 用户输入、生成结果、提示词正文、变量内容和剪贴板内容不进入匿名统计。
- 实时模式始终具有可见状态，并允许按应用排除。
- 用户可导出或清除全部本地数据。
- 首次启动时明确说明匿名统计范围，只有用户同意后才启用；拒绝不影响核心功能。

## 15. 异常处理与恢复

- **未配置模型**：进入配置向导，避免只展示技术错误。
- **Key 无效、余额不足或触发限流**：区分原因并给出相应建议。
- **网络中断或超时**：保留原文与已有部分结果，允许重试或切换模型。
- **用户继续输入**：取消过期任务，禁止旧结果覆盖新内容。
- **输入框失去焦点**：暂停插入并要求重新确认目标位置。
- **直接读取失败**：允许用户复制文本后继续优化。
- **直接写入失败**：保留结果并提供一键复制。
- **操作取消或应用异常退出**：不得造成原文丢失。
- **实时请求过密**：延长触发间隔并显示额度提示。

## 16. 兼容性定义

“支持所有输入场景”是产品追求的通用定位，不代表每个第三方应用都允许相同级别的系统控制。

兼容性分为两层：

1. 完整兼容：可读取选区或输入框、定位预览并确认插入。
2. 基础兼容：无法直接读取或写入时，通过复制、优化和粘贴完成任务。

首版重点验证浏览器中的 AI 对话框、常见网页输入框与富文本编辑器、macOS 原生文本区域，以及典型办公、聊天和代码编辑软件。测试覆盖中英文、长短文本、特殊字符、多显示器、全屏、深色模式和不同显示缩放。

## 17. 匿名统计与成效衡量

在用户同意后，可以记录：

- 应用安装与激活。
- 是否完成 API 配置和首次成功操作。
- 每周启动和使用天数。
- 提示词调用、模板填写和优化操作次数。
- 操作成功、取消或失败，以及非敏感错误类型。
- 实时模式是否启用。

不得记录：

- 用户输入和优化结果。
- 提示词正文与变量内容。
- API Key。
- 剪贴板内容。
- 用户在目标应用中的敏感信息。

成果评估顺序：

1. 产品与技术完成度：跨应用调用稳定、流程完整、异常可恢复、隐私边界清晰。
2. 真实用户数量：下载、激活和首次成功使用人数。
3. 持续使用情况：周活跃、重复使用、功能采用率和留存趋势。

## 18. 开发阶段

### 阶段一：系统能力验证

- 全局快捷入口。
- 读取选区或当前输入框。
- 在输入区域附近展示悬浮预览。
- 确认替换和剪贴板后备。
- 在代表性应用中验证兼容性。

阶段出口：证明最关键的系统交互可行且不会导致原文丢失。

### 阶段二：可用核心版本

- 固定提示词的创建、搜索和插入。
- 自定义优化规则。
- API Key 配置、连接测试和申请教程。
- 手动优化、流式预览、重新生成和确认插入。
- 本地安全存储、基础设置和主要异常处理。

阶段出口：新用户可以从安装开始，独立完成配置、调用提示词和第一次优化。

### 阶段三：完整首版

- 变量提示词模板。
- 分类、标签、收藏和最近使用。
- 实时模式与请求频率控制。
- 数据导入与导出。
- 更多应用兼容性与显示环境优化。
- 经用户同意的匿名统计。
- 完整新手引导与隐私说明。

阶段出口：形成适合公开展示和邀请真实用户使用的完整 macOS 产品。

### 后续方向

- 产品内置的云端 AI 与免费或付费额度。
- 账号、云同步和跨设备使用。
- 提示词及优化规则的公开分享与社区。
- Windows 版本。
- Apple 端侧模型或其他本地模型作为隐私与成本选项。

## 19. 首版验收标准

- 全局入口出现迅速，不明显打断输入节奏。
- 本地搜索和变量模板生成不依赖网络。
- 用户确认前原文绝不被修改。
- 用户始终可以取消、复制结果或恢复原文。
- 常见应用具备稳定的完整流程；受限应用可通过基础兼容流程完成任务。
- API Key 不以明文保存，敏感正文不进入日志或匿名统计。
- 实时模式包含停顿触发、最短文本限制、任务取消、频率限制和清晰状态。
- 从安装、授权、配置 Key 到完成第一次成功优化，新用户无需外部人工指导。
- 模型、网络、权限和插入失败均具有用户可理解的提示与恢复路径。

## 20. 已明确的产品约束

- 产品定位保持通用，不以某一职业作为用户边界。
- 首版以 macOS 原生体验为优先。
